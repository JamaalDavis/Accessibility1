Accessibility Principles

The four POUR principles underpin every component on this page.

  • Perceivable

  • Operable

    All functionality is keyboard accessible. A skip link bypasses the header. Focus indicators meet WCAG 2.2 SC 2.4.11 size and contrast requirements.

    Interactive widgets use native HTML elements. All custom patterns expose name, role, and value programmatically so current and future assistive technologies can interpret them.

Frequently Asked Questions

Built with native <details> and <summary> — no JavaScript required.

What is WCAG 2.2?

WCAG 2.2 is the Web Content Accessibility Guidelines version 2.2, published by the W3C in October 2023. It provides 87 success criteria organized under four principles: Perceivable, Operable, Understandable, and Robust (POUR). The AA conformance level is required by most accessibility laws worldwide.

What is new in WCAG 2.2?

WCAG 2.2 adds nine new success criteria. Key AA additions include SC 2.4.11 Focus Appearance (focus indicators must meet minimum size and contrast thresholds), SC 2.5.7 Dragging Movements (alternatives required for drag actions), and SC 2.5.8 Target Size Minimum (interactive targets must be at least 24×24 CSS pixels).

How do design tokens improve accessibility?

Design tokens define all visual properties — colors, spacing, typography — as named CSS custom properties. This prevents hard-coded values, ensures contrast decisions are auditable in one place, and makes global adjustments (e.g. a high-contrast theme) straightforward without touching component rules.

Which keyboard interactions are supported?

All interactive elements are reachable via Tab. The mobile navigation menu closes on Escape and returns focus to the toggle button. Disclosure widgets toggle with Enter or Space. Form fields validate on blur and announce errors via aria-invalid and aria-describedby.
